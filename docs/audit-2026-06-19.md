# Pleiades repo audit — 2026-06-19

Full-repo pass requested after the core build (inference, harness, webui) stabilized:
security, over-engineering, and general correctness. ~13,400 lines / 50 files in
`pleiades/`. Native `/security-review` and `ponytail-audit` skills were used where
they could run; the security pass had to be done manually (the skill requires a
session-level git checkout it didn't have here).

## Bottom line

No critical or security-critical issues. The vault, exec-tool gating, and webui
exposure are all solid. The one real **bug** worth fixing soon is that the agent
loops don't actually have the step cap their own docstrings claim. Everything else
is either a small cleanup or genuinely fine to leave alone.

## Fix soon

**Agent loops are uncapped despite documentation saying otherwise.** `engine.py`'s
`Engine._loop` (line 469) and `stream_events` (line 517), and `harness/agent.py`'s
`Agent.run` (line 212), are all `while True:` with no iteration ceiling. Both
modules' own docstrings say otherwise — `engine.py:9` ("loop (with a hard cap)")
and `agent.py:6-7` ("repeats until the model stops calling tools or the step cap
is hit"). The only real exits are the model stopping its own tool calls, or (harness
only) six consecutive model-call failures. A model that keeps calling tools never
stops on its own — that's a real cost/hang risk, not just a documentation nit.
Add an actual `max_steps`/`MAX_ROUNDS` check (the existing `eval_interval`
reflection-nudge logic is already counting rounds, so the ceiling is cheap to add
next to it).

**`pleiades/tools/browser.py` duplicates `pleiades/harness/builtins/browser.py`.**
The harness version (423 lines) is a strict superset — Camoufox + Playwright
fallback, CAPTCHA/challenge detection, clickable/input-field hints — while
`tools/browser.py` (145 lines) is a thinner, Camoufox-only reimplementation used
only by the legacy chat path. This is the one place the codebase didn't follow its
own pattern: `tools/search.py` already does this correctly, delegating to
`harness/builtins/web.py`'s `web_search()` in ~12 lines instead of reimplementing
SearXNG search. `tools/browser.py` should do the same against the harness browser
module. Net: roughly -120 lines, one less browser stack to keep in sync (and one
less surface where a future fix lands in only one of the two implementations).

**Uncommitted changes from this session.** `git status` shows `pleiades/autofit.py`,
`pleiades/launch.py`, and `tests/test_autofit.py` modified but not committed — this
is the `n_ubatch` autofit fix from earlier today. Worth a commit before it's
forgotten.

## Nice to have

- **Three sqlite connections in `webui/server.py` leak on exceptions** —
  `_memory_stats` (~318), `get_anamnesis_memory` (~840), `anamnesis_inspect` (~890)
  all do `con = sqlite3.connect(...)` / `con.close()` with the close only on the
  success path. A malformed or locked Anamnesis db leaks the handle. Wrap in
  `try/finally` or use the connection as a context manager.
- **`send_stdin` (`harness/builtins/process.py:164`) can never work.**
  `start_process` launches its `Popen` without `stdin=subprocess.PIPE`, so
  `proc.stdin` is always `None`. The tool's docstring promises support for
  "interactive programs"; in practice every call fails. Either wire up
  `stdin=PIPE` on `start_process` or drop the tool until it's real.
- **HTTP client inconsistency.** `harness/llm.py`, `harness/builtins/web.py`, and
  `harness/embeddings.py` use raw `urllib.request`/`urllib.parse` for HTTP, while
  the rest of the project (`fetch.py`, `models.py`, `inference/__init__.py`,
  `anamnesis.py`) uses `httpx`, which is already an unconditional dependency (not
  behind an extra). Not a bug, just inconsistent — worth converging on one client.
- **Stale pointer doc.** `Pleiades (1)/CLAUDE.md` (the empty-folder pointer file)
  claims `~/Pleiades/.venv/bin/python3.12` is the venv with dependencies installed
  and `.venv/bin/python` is a deps-less 3.13. On the real machine right now, there
  *is no* `python3.12` in `.venv/bin` at all — the venv's only interpreter is
  `python3` (a 3.13 symlink via `uv`), and it has every dependency installed and
  works fine (confirmed: `pytest` ran clean through it). The pointer doc should be
  corrected so a future session doesn't go looking for a binary that isn't there.
- **Test coverage gaps.** 19 test files cover 50 source files. Untested: `launch.py`,
  `runtime.py`, `harness/builtins/process.py`, `tools/email_box.py`,
  `connectors/discord_bot.py`, `tools/browser.py`, `cli.py`, `update.py`,
  `fetch.py`, `system_ops.py`, and — now most relevantly — the agent-loop logic
  itself in `engine.py`/`harness/agent.py` (the uncapped-loop bug above would have
  been caught by a test that asserts a ceiling exists).
- **Log file handle leak on a narrow path.** `pleiades/models.py` (~284-304): the
  log file is opened before `Popen`; if `Popen` raises `FileNotFoundError`
  (missing `llama_cpp.server` binary), the handle isn't closed. Rare, and process
  exit reclaims it anyway — lowest priority on this list.

## Confirmed fine, no action needed

- **Vault (`vault.py`).** Fernet encryption at rest, key from `PLEIADES_MASTER_KEY`
  or a generated `~/.pleiades/master.key` (mode 0600), passphrase-derived keys go
  through PBKDF2 at 480k iterations. Secrets are never logged; `Vault.list()`
  returns metadata only, never values; the only path to a decrypted value is the
  explicit `get()` call from a vault tool or the webui's one "reveal" endpoint.
- **Exec-tool gating is real, not just a docstring.** Every side-effecting tool
  (`run_shell`, `run_python`, `start_process`, `kill_process`, …) defaults to
  `safe=False` and is checked against `exec_policy` (`ask`/`allow`/`deny`, default
  `ask`) at four independent call sites: the legacy `ToolBelt.dispatch`
  (`tools/__init__.py:131`), the harness `Agent.execute_tool` (`agent.py:147`), the
  Claude-SDK `can_use_tool` permission callback (`claude_backend.py:82`), and the
  webui's `/api/work` approval flow (`server.py:1568`+), which blocks the worker
  thread on a real human-approval wait when policy is `ask`. The one acknowledged
  gap: `exec_policy=allow` is a total, documented bypass, and a caller can set it
  per-request on `/api/work` — fine for a single-user local tool, worth knowing if
  that endpoint is ever exposed beyond loopback.
- **Webui exposure.** Binds to `127.0.0.1` by default. A custom middleware
  (`webui/_guard.py`) rejects any request whose `Host` or `Origin`/`Referer` isn't
  loopback (or the explicit bind host) — a real DNS-rebinding/CSRF defense, not
  just a comment. No `CORSMiddleware` is installed, so there's no wildcard-CORS
  exposure either. Binding to a wildcard address (`0.0.0.0`) is treated as a
  deliberate "expose me" and prints an explicit warning while disabling the guard.
- **Path traversal.** Every profile-name-derived filesystem path (`profile_dir`,
  `vault_path`, `browser_dir`, avatar files) goes through `config.validate_name()`,
  which rejects path separators, `.`/`..`, leading/trailing dots or spaces, and
  names over 64 chars — checked directly, no traversal vector found.
- **Email/Discord credentials.** Always vault-sourced, never hardcoded. IMAP uses
  `IMAP4_SSL`; SMTP uses STARTTLS or implicit SSL depending on port — no cleartext
  credential transmission found.
- **Browser automation.** Optional dependency, persistent per-character profile
  dir, explicitly refuses to solve CAPTCHAs/verification challenges and hands off
  to the human instead of trying to punch through them.
- No bare `except:`, no mutable default arguments, no leftover `TODO`/`FIXME`/`XXX`
  anywhere in `pleiades/`.
- `harness/builtins/process.py`'s shared `_TABLE` and the webui's background-job
  dicts are properly lock-guarded — no races found.
- `pyproject.toml` dependencies are lean and correctly scoped into optional
  extras; no bloat.
- `harness/config.py` and `harness/anamnesis.py` are deliberate, documented
  compatibility/augmentation layers, not duplication.
